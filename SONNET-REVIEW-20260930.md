## Independent checks used

- **Decimal (60-digit) known values** computed in Python, a different implementation from the JS: e.g. CD 10,000 @ 4.5% × 2 yr = $10,920.25; 25,000 @ 3.75% × 2.5 yr = $27,410.08; 10,000 inflated 20 yr @ 3% = $18,061.11 (power $5,536.76); savings goal 30,000/5,000/5 yr/4% = $361.3945 → $361.40, interest $3,316.36, projected balance $30,000.36.
- **Exact BigInt rational oracles** for CD (integer years; 1,500 random + up to 400 constructed exact half-cent ties, at least 100 required), LTV (2,800 cases incl. ±1 cent around 80% and 96.5%) and DTI (2,500 cases incl. ±1 cent around 36/43/50%).
- **Month-by-month simulation** for savings goal (1,500 random goals): the displayed payment must reach the goal, one cent less must not, projected balance must match the simulation, and the lines must add up.
- **Integer loop** for emergency fund months-to-goal (1,200 random cases).
- Invalid batteries per tool: blank, negative, `1e309`, `-1e309`, non-numeric, over-range, astronomical result, recovery after an error. Zero principal/goal/value/expenses must *prompt*, not alert.
- Static checks: every control labelled, one polite live region, `role="alert"`, no fixed pixel widths/`nowrap`/tables in the tool markup, `max` on percent inputs, `docs/` pages contain the current script, site.css wrap rules intact.
- `extremes` suite: the largest accepted inputs render cleanly (no NaN/∞/exponent), e.g. CD `$999,999,999,999.99`, emergency fund `$120,000,000,000`.

## Actual limitations

- **No real browser was run.** The session is confined to this folder (file tools and shell both refuse paths outside it), so I did not look for or launch a headless browser. Layout is supported only by CSS reasoning (no fixed widths, wrap rules from Sept 27, rows wrap at 140 px) and static checks; please do the 320 px checks above. Screen-reader behaviour (`aria-live`, `role="alert"`) is verified as markup, not heard.
- **Savings goal changes a convention.** APY is now an *effective* yearly yield (what the label says), so the required monthly amount goes *up* by about 0.3% versus the old APY÷12 result (defaults: $361.40 now, about $360.41 before, which the old page rounded to "$360"), because a 4% APY earns slightly less per month than 4%/12 compounded. If you intended "nominal rate compounded monthly", relabel the field "interest rate (APR)" instead; the suite's APY test would then need to be inverted. Deposits are assumed at month end; payments are rounded up to the cent, so the projected balance is a few cents above the goal by design.
- **Rounding/validation choices are assumptions:** CD APY 0–100%, term ≤ 100 yr, deposit ≤ $1T; inflation rate 0–1,000% (deflation is not modelled; the field's `min=0` is unchanged); emergency-fund months 1–120; LTV amounts ≤ $10B (so integer products stay exact); DTI income/debts ≤ $1B. The LTV/DTI percentage is rounded to two decimals, so a ratio within 0.005 points of a threshold (for example 80.004%) can still read "80.00%" beside the next category's note.
- **Domain statements unchanged and not verified:** FHA 96.5%, ~97% conventional, 80% PMI, 28/36/43% DTI guidance, 3–6 months emergency fund. The text was left as written; only the arithmetic was reviewed.
- **Emergency-fund timeline ignores interest**, now stated on the page. CD assumes APY compounds once a year on the stated term and ignores early-withdrawal penalties and taxes.
- **`docs/sitemap.xml` lastmod** changed on all URLs (build side effect).
- **No mathematical certification** of these six beyond the listed behaviours, and none at all for the ~55 uncovered tools.
