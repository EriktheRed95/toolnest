Password Strength Checker

Check how strong a password is. See an entropy-bit estimate, a strength rating, and tips to improve it — all checked locally in your browser and never sent anywhere.

    How password strength is measured

    This checker estimates strength as entropy, measured in bits. The idea is simple: the more possible passwords an attacker would have to try, the stronger yours is. The number of possibilities depends on two things — how many different character types you use (the pool size) and how long the password is. The estimate is length × log2(poolSize), so each extra character adds a fixed number of bits while each new character type only widens the pool once.

    That's why length matters most. Going from 8 to 16 characters does far more for your security than sprinkling in a single symbol. Use this as a guide, not a guarantee: the math assumes truly random characters, so a long but predictable phrase or a previously leaked password can score well here and still be easy to guess. The safest approach is a unique, randomly generated password for every account, stored in a password manager.

    • Length first — every character multiplies the possibilities.
    • Mix types — combine lower, upper, digits, and symbols.
    • Stay unique — never reuse a password across sites.

    Your password is checked entirely in your browser and is never transmitted, logged, or stored.

    Frequently asked questions

    Is my password sent anywhere?
    No. The check runs entirely in your browser with JavaScript. Your password is never transmitted over the internet, logged, or stored — close the tab and it's gone. Even so, avoid pasting a password you actively use into any website you don't fully trust.
    How is strength estimated?
    It estimates entropy in bits from the size of the character pool (lowercase, uppercase, digits, symbols) and the password length, using bits = length × log2(poolSize). More characters and a larger pool mean more bits and a stronger password against brute-force guessing.
    What's a good number of bits?
    As a rough guide, under 50 bits is weak, 50–90 is fair to good, and over 90 bits is strong. Reaching high bit counts is easiest by adding length — every extra character multiplies the possibilities far more than swapping in one symbol does.
    Does this catch common passwords?
    Not directly — the entropy estimate assumes random characters. A long password built from a common phrase or a leaked password can score well here yet still be guessable. Always use a unique, randomly generated password for each account.
